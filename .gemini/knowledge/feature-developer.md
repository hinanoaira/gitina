# Knowledge: @feature-developer

## 1. Constraints (絶対遵守・禁止事項)
- **[C-01]** Gitコミット規約を遵守し、変更単位ごとに細かく分割して日本語・体言止めで記述すること。 (2026-11-11)
- **[C-02] リポジトリストレージのローカル固定とS3非サポート** (2026-11-11)
  - リポジトリ本体（bareリポジトリ）のストレージはローカルディスク（`Server.RepoRoot`）専用とする。`repository_storage` セクションやS3同期機構を再導入してはならない。ただし、Git LFSのS3サポート（`internal/lfs/storage_s3.go`）はこれと区別して維持すること。

## 2. Decisions (設計・技術選定の決定事項)
- **[D-01] 階層ディレクトリとリポジトリメタデータの保存方式** (2026-11-11)
  - **決定**: フォルダおよびリポジトリのメタデータ（visibility, collaborators）は該当ディレクトリ直下の `gitina-meta.json` に保存し、ルートから深さ順にカスケード継承する。
  - **理由**: 親ディレクトリに付与した権限が配下のリポジトリに自動反映され、専用DBなしでGitツリーと完全に整合するため。
- **[D-02] unlisted（限定公開）の権限分離** (2026-11-11)
  - **決定**: 一覧表示（`CanList`）では権限保持者のみ、直接参照（`CheckAccess`）では誰でも読み取り可能とする。
  - **理由**: YouTubeの限定公開と同様、URL直打ちでの共有を可能にしつつ、第三者の一覧には露出させないため。
- **[D-03] リポジトリストレージのローカル一本化** (2026-11-11)
  - **決定**: リポジトリ本体の S3 Tiered Storage（`internal/git/tiered/`）を廃止し、`repo.Manager`、`git.Handler`、`web.Handler` は直接ローカルファイルシステムを操作する。
  - **理由**: S3 bundle同期に伴う遅延・排他制御の複雑性を排除し、ローカルSSDでの高速・シンプルなGit操作と障害箇所の極小化を実現するため。
- **[D-04] Personal Access Token (PAT) のハッシュ化方式（Argon2id）** (2026-11-11)
  - **決定**: PATシークレットの保存・照合には `Argon2id`（PHC文字列形式 `$argon2id$v=19$m=65536,t=1,p=2$...`）を採用する。既存の SHA-256 ハッシュも検証可能とし、認証成功時に自動で Argon2id へアップグレード保存する。
  - **理由**: SHA-256 と比較して GPU・ASIC 耐性が高く、ブルートフォース攻撃に対する安全性を向上させるため。また自動移行により既存トークンの失効を防止するため。

## 3. Pitfalls (踏んだ地雷・既知の不具合と回避策)
- **[P-01] フォルダメタデータ保存時のディレクトリ不在エラー** (2026-11-11)
  - **事象**: 新規フォルダに対してメタデータを保存する際、実ディレクトリが存在せずファイル作成に失敗する。
  - **対策**: `SaveMetadata` 内で事前に `os.MkdirAll(repoDir, 0755)` を呼び出してディレクトリを確実に作成する。

## 4. Patterns (確立された実装パターン)
- **[PT-01] LFS ガベージコレクションの到達可能オブジェクト高速走査** (2026-11-11)
  - `git rev-list --objects --all --filter=blob:limit=1k` で1KB未満のblobのみを抽出し、`git cat-file --batch` で `oid sha256:...` をパース。7日間のGrace Periodを設けて誤削除を防止する。
- **[PT-02] ベアリポジトリのローカル存在確認と自動初期化** (2026-11-11)
  - リポジトリの存在判定は `filepath.Join(fullRepoPath, "HEAD")` の `os.Stat` で行い、存在しない場合は認証・書き込み権限のあるPush/Clone時にのみ `git.EnsureRepo` を呼び出してベアリポジトリを作成する。
